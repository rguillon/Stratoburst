<objective>
Run the Phase 1 go/no-go gate on real devices against the real static host, then ship the build to main.

Purpose: ROADMAP success criteria 1 and 3 can only be proven on real phones. WSL2's SwiftShader numbers do not count, and only the user owns the devices. CONTEXT Claude's Discretion asks for "a human-verify checkpoint where the user runs the `?debug&stress` link on their real phones and reports the numbers". This plan also validates D-04 PR previews live. It covers PLAT-01, PLAT-04 and PLAT-05.
Output: a PR preview link, the user's pasted reports, `01-DEVICE-REPORTS.md` with the verdict, and main deployed and verified.

Why the device checkpoint is `gate="blocking-human"` even though `workflow.human_verify_mode = end-of-phase`: the measurement must happen before the verdict task can compute anything, and auto-approving it would fabricate a performance pass. That is exactly the "default answer would be wrong to assume" case.
</objective>

## Phase Goal

**As a** friend with just the link, **I want to** load the game on my desktop or phone and fly a ship that shoots down targets over scrolling 3D terrain, **so that** I can play a Raiden-style shmup in the browser with no install or server. This is the ROADMAP Phase 1 goal mapped to story slots; see 01-01-PLAN.md for the sourcing note.

This plan's slice: the story is checked on the user's actual devices, and the stack gets a go/no-go.
