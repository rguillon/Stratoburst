<objective>

Anything that goes wrong (Python exceptions, JS errors, a blocked CDN, a timeout, a lost GPU context) produces an on-screen error panel instead of a frozen page, and `?crash=py|js` proves it.

Purpose: PLAT-03 (loading screen with progress, then a tap/click gate that unlocks audio) and PLAT-09 (on-screen error panel). ROADMAP success criteria 1 (loading/gate part) and 5 (crash flag).

</objective>

## Phase Goal

**As a** friend with just the link, **I want to** load the game on my desktop or phone and fly a ship that shoots down targets over scrolling 3D terrain, **so that** I can play a Raiden-style shmup in the browser with no install or server. This is the ROADMAP Phase 1 goal mapped to story slots; see 01-01-PLAN.md for the sourcing note.

This plan's slice: when I open the link I see it loading, I start it with a tap, and if anything breaks I am told instead of staring at a frozen screen.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Exception text (Python traceback, JS stack) → DOM | Error text may contain markup-like content, including echoed URL data |
| jsDelivr CDN availability → boot | Blocked or slow CDN must not hang the page |
| Global fetch → all network requests | The progress wrapper temporarily replaces a global |
| URL query (`?crash=`) → fault injection | A shared link can request an intentional crash |
