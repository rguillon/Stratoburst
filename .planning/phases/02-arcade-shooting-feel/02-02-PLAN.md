1. `web/src/fx/fx_dispatcher.js`: `export function createFxDispatcher({ handlers = [] } = {})` returns `{ dispatch(data, n), add(handler) }`. `dispatch` clamps n to `Math.floor(data.length / 6)` and, for each event, reads the six floats (type as `data[base] | 0`) and calls `handler.handle(type, x, y, a, b, c)` on every handler. It allocates nothing per event.
2. `web/src/fx/particle_system.js` (analog bullet_instances.js): `export function createParticleLayer({ capacity, blending = 'additive', name })` returns `{ mesh, emit(x, y, z, vx, vy, vz, life, size0, size1, r, g, b, gravity), update(timeS), get spawned(), capacity }`.
   - Geometry: an InstancedBufferGeometry of one unit quad with instanced attributes `aStart` (vec3), `aVel` (vec4: xyz velocity, w = gravity scale), `aLife` (vec2: spawn time, lifetime), `aSize` (vec2: start, end) and `aColor` (vec3, HDR allowed). Each is a DynamicDrawUsage InstancedBufferAttribute sized to capacity. Set `instanceCount = capacity`, `frustumCulled = false` and `mesh.name = name`.
   - Material: a ShaderMaterial with uniforms `uTime` and `uGravity` (a vec3 of (0, -60, 0) world units per second squared, scaled per particle by `aVel.w`). The vertex shader computes `t = uTime - aLife.x`. Outside `0..aLife.y` it collapses the quad off screen. Otherwise position = `aStart + aVel.xyz * t + 0.5 * uGravity * aVel.w * t * t`, and it billboards the quad in view space with size `mix(aSize.x, aSize.y, t / aLife.y)` and passes the normalised age. The fragment shader draws a soft disc whose alpha falls with age, then includes `<tonemapping_fragment>` and `<colorspace_fragment>` like bullet_instances.js.
   - `blending === 'additive'` uses `THREE.AdditiveBlending`, otherwise normal blending; both use `transparent: true` and `depthWrite: false`.
   - `emit` writes slot `head`, advances `head` modulo capacity and widens a dirty range. `update(timeS)` sets `uTime`, then for each attribute calls `clearUpdateRanges()`, `addUpdateRange(...)` over the dirty span (the whole buffer after a wrap) and sets `needsUpdate`, then resets the dirty range. Emit and update allocate nothing.
3. `web/src/fx/explosion_fx.js`: `export function createExplosionFx({ layers, events, blast, toWorld, getScale = () => 1, rng })` returns `{ handle(type, x, y, a, b, c) }`. On `type === events.EXPLOSION` with `a === blast.SMALL` it spawns on `layers.additive` at `toWorld(x, y, out)` (module-level scratch vector): one bright core flash (size 10 to 18, life 0.18 s, colour about (4.0, 2.6, 1.2)) plus 20 sparks in random horizontal directions (speed 30-70, life 0.35-0.6 s, size 2.5 to 0.5, colour about (3.2, 2.2, 0.9), gravity 0). `rng` defaults to a seeded mulberry32 defined in this module, so tests are deterministic.
4. `web/src/main.js`: after the bridge starts, create `const fxLayers = { additive: createParticleLayer({ capacity: 2048, blending: 'additive', name: 'fx-additive' }), normal: createParticleLayer({ capacity: 1024, blending: 'normal', name: 'fx-normal' }) }`, and add both meshes to `rig.scene` before the second `rig.prewarm()`. Create `createExplosionFx({ layers: fxLayers, events: manifest.events, blast: manifest.blast, toWorld: (x, y, out) => rig.toWorld(x, y, out) })` and `const fx = createFxDispatcher({ handlers: [explosionFx] })`. Each frame, immediately after `tick(...)`, call `fx.dispatch(bridge.channels.events, header[slots.EVENT_N])`. Keep `let fxTime = 0`, advanced by `dt / 1000`, and call `fxLayers.additive.update(fxTime)` and `fxLayers.normal.update(fxTime)` before `rig.render()`. Under `?debug`, expose `fx: { get particlesSpawned() { return fxLayers.additive.spawned + fxLayers.normal.spawned; } }` on `globalThis.__scorched`.
5. `tools/e2e/shooting.spec.js`: in "drones appear and can be shot down", after DRONES_DOWN >= 1, assert `__scorched.fx.particlesSpawned > 0`. Keep the error-panel check. Plan 02-04 renames the slots this spec reads.
